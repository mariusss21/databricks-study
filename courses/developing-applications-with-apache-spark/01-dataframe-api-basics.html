1.1 Lecture - DataFrame API Basics

The transformation toolkit for distributed data processing

This lecture covers the DataFrame methods, column references, built-in functions, and user defined functions you will use throughout this course, along with the Spark 4 ANSI mode behavior that affects type conversion.

Learning Objectives

By the end of this lecture, you will be able to:

  • Describe how distributed DataFrame transformations work across partitions and map to equivalent SQL operations
  • Work with Column objects and built-in functions, including proper column referencing and manipulation
  • Apply DataFrame methods and built-in functions to perform common data transformation tasks in a distributed environment

A. DataFrame Transformation Methods

The core methods for distributed data transformation:

  • DataFrame operations are distributed automatically across all partitions, enabling parallel processing of large datasets
  • All DataFrame transformations have equivalent SQL operations under the hood (e.g. select() maps to SELECT, filter() maps to WHERE)
  • Methods return a new DataFrame rather than modifying the existing one, supporting immutable transformations
  • Each operation builds upon the logical plan until an action triggers execution
DataFrame Method SQL Equivalent Description
__select()__ SELECT Choose specific columns
__filter()__, where() WHERE Filter rows based on a condition
__groupBy()__ GROUP BY Group rows for aggregation
__orderBy()__, sort() ORDER BY Sort a DataFrame by columns
__join()__ JOIN Combine two DataFrames by a key

For more information see the DataFrame API reference.

▶ Transformations build a plan, actions execute it

B. Referencing DataFrame Columns

There are several ways to reference a column, and they are not all equal:

Type Description Example
__Direct__ Simplest syntax, works for basic column selection df.select("name")
__By attribute__ Only works for column names that are valid Python identifiers df.select(df.first_name)
__Column expression__ Works with any column name, can be referenced across DataFrames (e.g. in joins) df.select(df["first-name"])
__Column object__ Required when building complex expressions or using column-specific operations like alias(), cast(), asc() or desc() df.select(col("name").alias("customer_name"))

Common Column Object Methods

Method Description Example
__alias()__ Rename a column col("name").alias("customer_name")
__cast()__ / __astype()__ Change data type col("age").cast("int")
__isNull()__ / __isNotNull()__ Check for nulls col("name").isNotNull()
__contains()__ String matching col("title").contains("Manager")
__asc()__ / __desc()__ Sort direction (used with sort / orderBy) df.sort(col("c1").desc(), col("c2").asc())

For more information see the Column API reference.

C. Built-in Functions

Spark ships with a large library of functions that operate on columns:

  • Functions can operate on scalar (strings, ints, etc.) or complex data types (arrays, structs, etc.)
  • Function categories include Math, Datetime, String, Collection, Aggregate, Window, and more
  • The same functions are available in both DataFrame operations and SQL queries using the equivalent SQL function names
Built-in Function SQL Equivalent Description
__round(col, scale)__ ROUND Round a number to a scale
__concat(col1, col2)__ CONCAT Concatenate strings
__date_format(col, fmt)__ DATE_FORMAT Format dates as strings
__regexp_replace(col, pattern, replace)__ REGEXP_REPLACE Replace using a regex
__coalesce(col1, col2)__ COALESCE First non-null value

For more information see the functions reference and the SQL function reference.

D. Handling Missing Values

Real data has gaps. Common functions for handling nulls:

  • isNull() / isNotNull() - check if values are null
  • count(col) - counts non-null values in a specific column
  • df.fillna() / df.na.fill() - replace nulls with values
  • df.dropna() / df.na.drop() - remove rows with nulls
# Drop rows with nulls in a specific column
df.dropna(subset=["my_column"])

# ..or..
df.na.drop(subset=["my_column"])

# Replace nulls with a value
df.fillna("unknown")

# ..or..
df.na.fill("unknown")

E. Type Conversion Under ANSI Mode

Spark 4 enables ANSI SQL mode by default, which changes how invalid conversions behave:

Expression Spark 3 (ANSI off) Spark 4 (ANSI on)
__CAST('NA' AS INT)__ Returns NULL silently Raises an error
__try_cast('NA' AS INT)__ Returns NULL Returns NULL
Integer overflow Wraps around silently Raises an error
⚠️
Use try_cast() for Dirty Data

When cleaning data of unknown quality, use try_cast() (or the Column method col("c").try_cast("int")) so invalid values become NULL that you can then detect and handle, instead of failing the whole job.

F. User Defined Functions

UDFs allow you to apply your own Python functions to DataFrame columns:

from pyspark.sql.functions import udf

# define your function
@udf("string")
def make_greeting(name):
    return f"Hello, {name}!"

# use your function
df.select(make_greeting("name"))
  • UDFs allow developers to create reusable custom functions
  • UDFs can adversely impact performance: they cannot be optimized by the Catalyst optimizer and add serialization overhead between the JVM and the Python worker
  • Always use a built-in function if one is available

Pandas UDFs and Apache Arrow

Pandas UDFs let you write Python functions that operate on batches of rows instead of single rows, leveraging Apache Arrow for more efficient Python-JVM serialization.

from pyspark.sql.functions import pandas_udf

# define your pandas udf
@pandas_udf("integer")
def age_plus_one(age_series):
    return age_series + 1

# use your pandas udf
df.select(age_plus_one("age"))
  • More efficient than their non-pandas counterparts
  • In Spark 4 you can also accelerate row-based UDFs with Arrow serialization: @udf("string", useArrow=True)
  • You should still use a built-in function if one is available - built-ins are always fastest because the optimizer understands them

Summary

  • DataFrame transformations map one-to-one to SQL operations and are distributed across partitions automatically
  • Use Column objects (col()) for complex expressions and column methods like alias() and cast()
  • Prefer built-in functions; reach for pandas UDFs when custom logic is unavoidable
  • Spark 4 ANSI mode makes invalid casts fail loudly; try_cast() provides the permissive alternative for cleaning dirty data
