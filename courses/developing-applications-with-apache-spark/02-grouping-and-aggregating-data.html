2.1 Lecture - Grouping and Aggregating Data

From rows to insight: distributed aggregation in Spark

This lecture covers grouping and aggregation with the DataFrame API: how groupBy() works across a cluster, the core aggregation methods, combining multiple aggregations, and window functions for analytics that preserve row-level detail.

Learning Objectives

By the end of this lecture, you will be able to:

  • Describe distributed grouping transformations for data aggregation and their mapping to SQL GROUP BY syntax
  • Apply and combine multiple aggregation functions using both DataFrame methods and SQL expressions
  • Use window functions for advanced analytics including ranking, running calculations, and comparative analysis across rows

A. Introduction to groupBy Operations

The foundation of data aggregation in Spark:

  • groupBy() operations in Spark partition data across nodes based on the grouping columns
  • Aggregations execute in parallel across partitions for optimal performance
  • Similar to SQL GROUP BY syntax but with more flexible options
  • Supports multiple columns for complex grouping patterns
  • groupBy() returns a GroupedData object that lets you chain aggregation methods like count(), sum(), avg() - this is lazily evaluated until an action triggers execution
▶ Grouping shuffles rows so each group lands on one Executor

groupBy Examples

Grouping is generally a precursor to aggregation:

# Basic grouping
df.groupBy("department").count()

# Multi-column grouping
df.groupBy("department", "location").avg("salary")

# Using column expressions
df.groupBy(col("department"), year("hire_date")).sum("revenue")

B. Basic Aggregation Methods

The most common aggregation methods available on grouped data:

Method SQL Equivalent Description
__count()__ COUNT(*) Count rows in each group
__sum(col)__ SUM(col) Sum values in a column for each group
__avg(col)__ AVG(col) Average of column values for each group
__min(col)__ / __max(col)__ MIN / MAX Extremes of column values for each group

For more information see the grouping API reference.

C. Combining Multiple Aggregations

Multiple aggregations can be performed on the same GroupedData object using the agg() function:

# Using aggregate functions directly
df.groupBy("department") \
  .agg(sum("salary").alias("total_salary"),
       avg("age").alias("avg_age"))

# Alternative syntax using a dictionary
df.groupBy("department").agg({
    "salary": "sum",
    "age": "avg"
})
ℹ️
agg() and Aliases

agg() is also needed when you want to alias the result of a single aggregation function - the shortcut methods like sum() generate column names such as sum(salary) that are awkward to reference downstream.

D. Window Functions

Aggregation without losing row-level detail:

  • What are they? Special functions that perform calculations across a set of rows related to the current row
  • When to use:
    • Calculating running totals and averages
    • Ranking records within groups
    • Accessing previous and next row values
    • Comparing row values to group aggregates

Window Example

A window specification defines how rows are partitioned and ordered; window functions are then applied over() it:

from pyspark.sql.window import Window
from pyspark.sql.functions import rank, sum, lag

# Window specification
windowSpec = Window.partitionBy("department").orderBy("salary")

# Using window functions
df.withColumn("rank", rank().over(windowSpec)) \
  .withColumn("running_total", sum("salary").over(windowSpec)) \
  .withColumn("prev_salary", lag("salary").over(windowSpec))
💡
groupBy vs Window

groupBy() collapses each group to a single output row. A window function adds the aggregate to every row, preserving the original detail - choose based on whether you still need the individual rows.

Summary

  • groupBy() redistributes rows by key (a shuffle) and aggregates each group in parallel, mirroring SQL GROUP BY
  • Shortcut methods (count(), sum(), avg(), min(), max()) cover single aggregations; agg() combines several and supports aliases
  • Window functions calculate aggregates, rankings, and offsets across related rows while keeping row-level detail
  • Everything is lazily evaluated - the shuffle and aggregation only run when an action is triggered
