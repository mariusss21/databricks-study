1.1 Lecture - Apache Spark and Databricks

The platform context that shapes every Spark workload you will monitor and optimize

This lecture covers the Databricks platform built by the creators of Apache Spark: the Lakehouse and Medallion architectures, Workspaces and Unity Catalog, and the runtime and compute options your workloads run on, including what Apache Spark 4 brings to Databricks Runtime 17.3 LTS.

Learning Objectives

By the end of this lecture, you will be able to:

  • Describe the background and core components of the Databricks platform
  • Explain the Lakehouse paradigm and the Medallion reference architecture
  • Describe the organizational concepts of Workspaces and Unity Catalog
  • Compare Databricks runtime and compute options for different workloads, and identify the major Spark 4 changes that affect them

A. Databricks Background

A unified data and AI platform built by the creators of Apache Spark.

  • Founded in 2013 by the original creators of Apache Spark
  • Built on open source foundations: Apache Spark, Delta Lake, and MLflow
  • Available on all major cloud platforms with a consistent experience
  • Pioneered the Lakehouse and Medallion architectures
Open Foundations
Apache Spark, Delta Lake, and MLflow keep your data and code portable across clouds and engines.
Unified Platform
Collaborative notebooks, jobs, governance, and ML on one platform with enterprise-grade security.
Optimized Performance
Proprietary enhancements such as Photon and predictive optimization accelerate open source Spark.

B. The Lakehouse

A unified architecture combining the data warehouse and the data lake.

  • The structure of the data warehouse with the extensibility of the data lake
  • Scalability via separation of storage and compute
  • Support for all data types: structured, semi-structured, and unstructured
  • Unified batch and stream processing support
  • Built-in security and governance
▶ How the Lakehouse combines both worlds

C. Medallion Architecture

A structured approach to data transformation and quality in the Lakehouse.

Tier Role Characteristics
Bronze Like-for-like source copy with history Raw, append-heavy, schema preserved (the data lake)
Silver Cleaned and conformed data Validated, deduplicated, not yet aggregated
Gold Business-level features and aggregates Consumption-ready for BI, ML, and data products

D. Databricks Workspaces

Isolated, collaborative environments for organizations, departments, teams, or projects.

A workspace bundles everything a team needs:

  • Compute resources: Spark clusters and serverless SQL warehouses
  • Directories and notebooks
  • Jobs: Lakeflow jobs and pipelines
  • Access to objects in Unity Catalog: tables, views, functions, models, and more
  • Simplified governance, security, and access control

E. Unity Catalog

Unified data governance and security across your Databricks Lakehouse.

CORE FUNCTIONS
  • Single control plane for all data assets
  • Fine-grained access control (tables, columns, rows)
  • Automated data lineage tracking
  • Centralized auditing and compliance
WHY UNITY CATALOG
  • Manages data and AI assets across workspaces
  • Simplifies security and governance
  • Provides data discovery and sharing
  • Three-level namespace: catalog.schema.table

In this course you work in your own catalog with a course schema (spark_perf), reading source data from the shared samples catalog.

F. Databricks Runtimes and Compute

Purpose-built environments optimized for different workloads.

The Databricks Runtime (DBR) is a pre-packaged and tested combination of Spark core and peripheral components that simplifies operations and boosts performance:

Runtime Purpose
Standard Runtime Base Apache Spark with Databricks optimizations
Machine Learning Runtime Pre-configured with popular ML libraries
Photon-enabled Runtime Native vectorized engine for SQL performance

Each runtime release pins a Spark version: Databricks Runtime 17.3 LTS, used in this course, ships Apache Spark 4.0. Your compute options for running it:

Compute Best for
All-purpose clusters Interactive development and analysis
Job clusters Automated production workloads
SQL warehouses and serverless No cluster management, instant start
ℹ️
Why this course uses Classic Compute

Serverless compute hides the cluster, and with it the Spark UI. Because this course is about monitoring and optimizing Spark, the demos and labs use a Classic Compute cluster so you can inspect jobs, stages, tasks, and execution plans directly.

G. What's New in Apache Spark 4

Spark 4 is the largest Spark release in years. The changes most relevant to this course:

Feature What it means
ANSI SQL mode on by default Invalid casts and arithmetic overflows now fail loudly instead of silently returning NULL
VARIANT data type Fast, flexible storage for semi-structured JSON-like data
SQL scripting and session variables Procedural SQL blocks, DECLARE, and EXECUTE IMMEDIATE
Spark Connect A thin client-server protocol decoupling applications from the Spark driver
Structured logging Spark logs are emitted as JSON, making driver and executor logs queryable with Spark itself
Adaptive Query Execution refinements AQE remains on by default and continues to re-optimize plans at runtime
💡
Monitoring angle

Structured logging is a monitoring feature: because Spark 4 log files are JSON, you can load them into a DataFrame and analyze failures and warnings with the same engine that produced them.

Summary

  • Databricks is a unified data and AI platform built by the creators of Apache Spark on open source foundations
  • The Lakehouse combines warehouse structure with data lake scale; the Medallion architecture organizes data into Bronze, Silver, and Gold tiers
  • Workspaces organize people and resources; Unity Catalog governs data with fine-grained access control and lineage
  • Databricks Runtime 17.3 LTS ships Apache Spark 4.0, with ANSI mode on by default, structured logging, and AQE on by default
  • This course uses Classic Compute so the Spark UI and execution plans are visible
