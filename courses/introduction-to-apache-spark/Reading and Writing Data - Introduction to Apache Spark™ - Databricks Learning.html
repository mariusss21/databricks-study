2.2 Lecture - Reading and Writing Data

DataFrame I/O, schemas, data types, and Spark SQL

This lecture covers the interfaces Spark provides for getting data into and out of DataFrames, how schemas and data types work, and how Spark SQL and the metastore fit in.

Learning Objectives

By the end of this lecture, you will be able to:

  • Use the DataFrameReader and DataFrameWriter interfaces for data I/O
  • Define DataFrame schemas by inference, with StructType objects, and with DDL strings
  • Identify common primitive and complex Spark data types, including the VARIANT type
  • Explain how Spark SQL and metastores (Unity Catalog) relate to DataFrames

A. DataFrameReader and DataFrameWriter

The DataFrame API provides two interfaces for data I/O.

DataFrameReader (accessed as spark.read):

  • Supports multiple formats (CSV, JSON, Parquet, ORC, Delta, and more)
  • Provides schema inference
df = spark.read.format("csv").option("header", "true").load("/path/to/csv-dir")

# or using predefined format readers
df = spark.read.csv("/Volumes/catalog/schema/files/csv-dir")
df = spark.read.parquet("s3://mybucket/parquet-dir")

DataFrameWriter (accessed as dataframe.write):

  • Flexible output formats and partitioning
  • Supports various save modes (overwrite, append, and more)
df.write.format("parquet").mode("overwrite").save("/path/to/output-dir")

# or using predefined format writers
df.write.csv("/Volumes/catalog/schema/files/csv-out")
df.write.saveAsTable("my_catalog.my_schema.my_table")

B. DataFrame Schemas

Every DataFrame has a defined schema - the structure and data types of all its columns. A schema can be inferred from the data or explicitly specified (more efficient):

# Defining a schema explicitly
from pyspark.sql.types import StructType, StructField, StringType, IntegerType
schema = StructType([
    StructField("name", StringType()),
    StructField("age", IntegerType())
])
  • Self-describing formats like Parquet and Delta include schema information, so no inference is needed
  • Use the printSchema() method to print out a DataFrame's schema
⚠️
Schema Inference Costs

Inferring a schema requires an extra pass over the data and can guess wrong (for example reading a postal code as an integer). For production pipelines, define schemas explicitly.

DDL Schemas

Instead of defining schemas using StructType objects, you can use DDL (Data Definition Language) strings for more readable schema definitions:

# Defining a DDL schema
ddl_schema = "name STRING NOT NULL, age INT, city STRING"

# Using the schema
df = spark.read.csv("/Volumes/catalog/schema/files/csv-dir", schema=ddl_schema)
df.printSchema()

C. DataFrame Data Types

Spark defines a rich set of primitive data types, exposed both as Python type objects and SQL type names:

pyspark.sql.types Spark SQL Type Python equivalent
__ByteType__ TINYINT int
__ShortType__ SMALLINT int
__IntegerType__ INT int
__LongType__ BIGINT int
__FloatType__ FLOAT float
__DoubleType__ DOUBLE float
__BooleanType__ BOOLEAN bool
__StringType__ STRING str
__BinaryType__ BINARY bytearray
__TimestampType__ TIMESTAMP datetime.datetime
__DateType__ DATE datetime.date

Complex and Semi-Structured Data Types

Spark also supports complex types for nested data, plus the VARIANT type introduced in Spark 4:

DataType SQL Type Python equivalent Notes
__ArrayType__ ARRAY list (or tuple) Ordered elements of the same type
__MapType__ MAP dict Keys and values can have different types
__StructType__ STRUCT tuple, dict, namedtuple Named fields with specified types
__VariantType__ VARIANT - Open semi-structured values (such as JSON) stored in an optimized binary form; new in Spark 4

For more information see the data types reference.

💡
VARIANT for JSON

Before Spark 4, semi-structured JSON was typically stored as a STRING and parsed on every query. VARIANT stores the parsed structure in a binary form, so path expressions like data:order.items[0].sku are both more convenient and significantly faster.

D. Spark SQL

Spark SQL is the SQL interface to the same engine that runs DataFrames - the two are interchangeable.

DataFrame registration:

  • Temporary views: createOrReplaceTempView()
  • Global temp views: createGlobalTempView()
  • Registration enables SQL queries against DataFrames

SQL query execution:

  • Use spark.sql() to run SQL statements from Python
  • Results come back as DataFrames, so SQL and DataFrame code compose seamlessly
  • Full SQL support including complex types, expressions, and the built-in functions library
df.createOrReplaceTempView("flights_temp")
result_df = spark.sql("SELECT carrier, COUNT(*) AS flights FROM flights_temp GROUP BY carrier")

E. A Primer on Metastores

A metastore provides the metadata management for Spark SQL. It is responsible for:

  • Defining table schemas and locations
  • Defining table partitions
  • Storing properties and information for objects including tables, views, and functions

Unity Catalog is the centralized metadata service provided for Databricks accounts and assigned to Databricks workspaces. It enables fine-grained security and governance across all data assets, organizing them in a three-level namespace: catalog.schema.table.

Summary

  • spark.read (the DataFrameReader) and df.write (the DataFrameWriter) handle all DataFrame I/O
  • Schemas can be inferred, defined with StructType objects, or defined with readable DDL strings - explicit is preferred
  • Spark provides primitive, complex, and (new in Spark 4) VARIANT data types
  • Spark SQL and the DataFrame API are two interfaces to the same engine; temp views bridge between them
  • Unity Catalog is the metastore in Databricks, governing tables, views, volumes, and more
