Databricks · Associate cert

Mon 16 Nov deep dive * + docs
Pipeline = what to compute (ST · MV · AUTO CDC); Job = when, which branch, what to repair.
  • Streaming table: each record processed once; append-only source ✓
  • Materialized view: recomputed to current state; aggregations, joins ✓
  • AUTO CDC (ex APPLY CHANGES): CDC feed → SCD1/2 target ✓
  • SEQUENCE BY: sortable order column; STRUCT(ts, id) breaks ties ✓
  • Repair run: re-runs unsuccessful tasks + their dependents ✓
Pipeline mode ✓

Exam traps
  • Job mode overrides pipeline mode; prefer a continuous job ✓
  • If/else: == / != compare strings (12.0 == 12 false); < > numeric ✓
  • Repair ≠ idempotent: partial append + repair = duplicates ✓

AI Engineering

Wed 18 Nov deep dive
An eval isn’t a test suite, it’s a measurement loop: validate every instrument.
  • Task · trial · transcript · outcome: test case · one attempt · full record · final env state ✓
  • Grader: logic scoring one aspect: code, model or human ✓
  • Error analysis: open → axial coding → counted taxonomy; stop at saturation ◦
  • LLM judge: narrow, binary, critique first; report TPR/TNR + kappa on frozen test ◦
  • pass@k / pass^k: ≥1 of k trials succeeds / all k succeed ✓
  • Capability / regression eval: “can it?” / “still can?” (~100 % pass) ✓
  • Gates: regression blocks any new failure; capability = paired, clustered test ◦
Traps
  • 5 % defects: an always-“pass” judge scores 95 % agreement, catches nothing ◦
  • 200 tasks at 80 % → 95 % CI ≈ ±5.5 pts: a +2 is noise (illustrative) ◦
  • Grader bugs: CORE-Bench 42 % → 95 % after fixing grading and specs ✓
Recall: the loop’s stages · pass@k vs pass^k · TPR/TNR, not agreement.

Data Eng · US senior interviews

Fri 20 Nov deep dive
Correct (LSN) · at scale (config) · safe (tests) · right-sized (triggered).
  • Log-based CDC: reads the WAL, sees deletes; query-based misses them ◦
  • LSN: Postgres log position = the source’s own order ◦
  • Debezium op: c create · u update · d delete · r snapshot read ✓
  • Tombstone: null-value event after a delete, same key ✓
  • Metadata-driven: one pattern + one config entry per table ◦
  • Zombie row: late update re-inserted after a hard delete ◦
Gotchas
  • Loop closure: all flows read the last entry → factory fn ◦
  • Delete a YAML entry → pipeline drops that table; require retired: true ◦
  • AUTO CDC keeps tombstones 2 days by default (tombstoneGCThresholdInSeconds) ✓
  • Test layers: config contract → pytest → dev integration → runtime expectations ◦
Recall: 4 hard CDC problems (order · dupes · deletes · late) · 4 test layers.
